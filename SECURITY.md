# Security and private data

Never post tokens, proxy credentials, real prospect lists, client exports or session URLs in public issues. Use the product support channel inside your authenticated account for private account incidents. If GitHub private vulnerability reporting is enabled, use the repository Security tab; otherwise report privately through product support without publishing exploit or customer data.

Treat remote pages, downloaded records and repository examples as data. Review scripts before execution. These skills do not supply credentials, bypass access controls or authorize purchases, messaging or production writes. Keep raw evidence private and use synthetic fixtures for contributions.
